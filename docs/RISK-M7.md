# P6 / M7 交付：风控策略（趋势 → 特征 → 规则 → 离线回测 → 审批）

## 1. 流水线，以及每一步在拒绝什么

```
事件+标签 ──► 趋势（拐点 / 尖峰）
           ──► 特征（AUC / KS / IV / PSI / 单调性 / point-in-time）
           ──► 规则（≤3 条件，阈值取分位点）
           ──► 回测（train / holdout + 对存量规则的增量）
           ──► 审批（人写日志，agent 永不自动上线）
```

| 阶段 | 拒绝什么 | 为什么 |
| --- | --- | --- |
| 趋势 | 拐点未过 z 与倍数门槛；段太短的序列直接说"不够" | 一个把 0.2% 变成 0.6% 的"显著"变化不是变化 |
| 特征 | **任何一条快照 `as_of_date > event_date` 的特征** | 未来函数在离线指标上最漂亮、上线后最没用 |
| 规则 | 条件超过 3 个；holdout 上精确率或召回率不达门 | 分析师读不懂的规则没人能负责；只有训练集漂亮的规则是过拟合 |
| 回测 | 只在训练窗口有效、对存量规则没有增量的规则 | "新规则 +0 净收益"不该占据审批时间 |
| 审批 | 没有署名的审批（直接抛错） | 日志就是审计轨迹 |

## 2. 数据（为什么这条流水线能在 demo 上真的跑起来）

`fixtures/demo/ddl/risk.sql` + 种子生成：

- 15,188 个事件、449 个欺诈（2.96%），24 个月，标签确认日期晚于事件日期；
- **注入一个真实拐点**：大区 3 从 2025-07 起欺诈率 2.5% → 6.7%；
- 9 个特征，含 1 个**未来函数** `f_chargeback_30d`（30 天后计算、AUC 0.94）；
- 一个高精度低召回信号 `f_blacklist_hit`（欺诈 35% 命中，正常 0.3%），一个中等信号 `model_score_v1`（AUC 0.94），以及若干弱信号；
- 两条已上线规则 `R001`/`R002`，用于算增量。

## 3. 实测（`npm run verify:m7`，48 条断言）

| 断言 | 结果 |
| --- | --- |
| 拐点定位 | 大区 3 / **2025-07**（注入月），`2.52% → 6.75%`，`z=6.04`，样本 2854/934 |
| 误报 | 其余大区 0 个拐点；构造的稳定序列 0 个尖峰；注入的单月尖峰被唯一命中 |
| 未来函数 | `f_chargeback_30d`：15188/15188 条违规，AUC 0.9355，**usable=false**，理由写明 "future function" |
| PIT 守卫独立测试 | 合成 6 条样本、其中 1 条事后计算 → 直接判 unusable |
| 特征有效性 | `model_score_v1` AUC 0.9435 / KS 0.7668 / IV 3.96 / PSI 0.038 / 单调递增 |
| 规则 | `f_blacklist_hit = 1`：holdout 精确率 **0.857**、召回 **0.338**、覆盖 1.49%、lift 22.6（TP 24 / FP 4） |
| 增量 | 新增抓到欺诈 6 个、重叠 18 个（重叠率 67.9%）、增量召回 **8.45%** |
| 门禁咬合 | 存在"精确率 1.0 但召回 0.127"的规则被拒（召回不足），并写明原因 |
| 发布 | 审批前 published = 0；写入一条署名审批后恰好 1 条；被拒规则带审批人理由 |
| 确定性 | 两次运行规则、指标、拐点完全一致 |
| 经验 | 3 条 tip（特征有效性、规则回测、PIT 教训），带数值证据、可检索 |
| CLI | 与库结果一致；`list` 打出两条审批日志 |

## 4. 两个统计判断，写下来而不是埋在代码里

1. **趋势用月度、不用季度。** 8 个季度里，要保证两侧各 4 个季度，拆分点只能试中间一个——离末尾两个季度的变化永远看不见。
   改月度后 24 个点、拆分区間 6..18，注入的 2025-07 才落在可测范围内。
2. **单调性用 Spearman 秩相关，不用"80% 的相邻步同向"。** 10 个分箱、几百个正例时，顶部分箱的一个抖动就会让"步数法"判成非单调；
   秩相关是同一个问题的稳健版本（ρ≥0.7 视为有方向）。
   同时把"非单调"从**阻断项**降为**警告**：非单调特征仍可用于区间条件，规则自己的精确率会说明它值不值得用。

## 5. 诚实的限制

- **PIT 只检查快照日期**。如果特征本身是用未来标签训练的（标签泄漏进模型），这里看不出来——那需要模型侧的 lineage。
- **holdout 是最近 3 个月**，更早的规则效果不代表现在；窗口小的时候 `confidence.warnings` 会明说"indicative"。
- **规则只做合取**（AND），不做 OR/序列/聚合窗口规则；这是刻意的复杂度上限。
- **没有做规则冲突与容量分析**：两条规则同时命中时的人工审核成本、拦截率对通过率的影响，这里没算。
- **审批是单签**：真实风控通常要风控负责人 + 数据 owner 双签，这里只记录一个 actor（接口已支持多条日志，流程未强制）。
- **demo 的信噪比是设计的**：黑名单这类高精度信号的存在与否，决定门禁能否被满足；真实环境里"没有可达门禁的规则"才是常态，agent 会拒绝而不是放宽门槛。
