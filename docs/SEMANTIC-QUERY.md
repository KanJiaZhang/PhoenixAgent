# M2.5 交付：语义层的问数面（确定性解释器 + translate/ask/validate）

## 1. 为什么不用 LLM 解析问题

LLM 能解析更多问句，也会偶尔把「各渠道营收」理解成「总营收」，然后给你一个**正确但答错问题**的数字。
这正是基座在 `docs/DATA-AGENT.md` §10 里用两次返工换来的教训。所以这一层的取舍是：

- **词表来自模型**：指标名/别名、维度名/别名、以及一张很短的业务同义词表（花费/营收/大区…）。
  表里每一项都映射到模型里**已经存在**的指标名；映射不到就忽略，绝不凭空生成指标。
- **分解词没有匹配维度 → 拒绝**。「各」「按」「每个」「分别」要求分解，回一个总数就是错答案；拒绝时列出可用维度。
- **歧义 → 拒绝**。两个指标/维度以同样长度命中，列候选让人选。
- **时间不猜**。问题里有年份但模型里没有时间维度 → 带原因的拒绝，而不是一个悄悄匹配不到任何行的过滤。

## 2. 三个端点

| 端点 | 行为 |
| --- | --- |
| `POST /v1/semantic/translate` | 问题/规格 → SQL + M3 的 findings，**不执行** |
| `POST /v1/semantic/ask` | 解释 → 渲染 → 校验 → 执行 → 带 provenance 的答案 |
| `POST /v1/semantic/validate` | 只编译（`LIMIT 0`），返回能否跑、SQL 与 findings |

`QuerySpec` 是三者共用的货架：`{metric, dimensions[], period{from,to,grain}, compare, topN, descending, matched}`。
`ask` 里的 SQL 就是 `provenance.sql`，不是重新渲染的第二份。

时间过滤是**半开区间**（`>= from AND < to`），因为 `BETWEEN '2025-11-01' AND '2025-11-30'` 会漏掉 `11-30` 的
`23:59:59`，这类边界 bug 在报表里很常见。

## 3. 实测（`npm run verify:m2q`，40 条断言）

| 断言 | 结果 |
| --- | --- |
| 「2025 年 11 月各大区花费」解析 | `metric/spend` + `dim/region` + `[2025-11-01, 2025-12-01)` |
| 总数 = 手写 SQL | 4,908,324.46（误差 <1e-9） |
| 分组行之和 = 总数；单个切片 = 它自己的 SQL | 华东 1,282,718.35 |
| 同比 | 对比窗口 2024-11 = 4,352,997.67，Δ = 555,326.79（+12.76%） |
| top-N | 2 行、按值降序、`partial: true` 且 limits 写明"total 是前 2 项之和" |
| 未知指标 | `no-such-metric`，列出 17 个候选 |
| 「各渠道 GMV」 | `no-such-dimension`，并列出 gmv 可用的 5 个维度 |
| 同时点两个指标 | `ambiguous` |
| provenance | 指标、表达式、SQL、半开过滤、行数、执行位置齐备 |
| translate | 有 SQL、无答案、有 findings |
| 相同问题 | SQL 与数值逐字节一致 |
| HTTP | `ask`/`translate`/`validate` 三条路由行为一致；refusal 是 200 不是 500；目录里能查到这三条 |

## 4. 一个被验收抓住的 bug

`top-N` 最初把渲染器的 `ORDER BY 1` 改成 `ORDER BY 1 DESC LIMIT n`——而 `1` 是**维度列**，于是返回的是
"名字排最前的两个大区"，不是"花费最高的两个"。验收里的 `rows[0] >= rows[1]` 直接失败。修法：top-N 时删掉
原排序、改为 `ORDER BY value DESC`（按度量别名）。

## 5. 诚实的限制

- **词表是有限的**：同义词表是产品词表（不是模型学出来的）。表外的说法会拒绝并列出可用词汇——这是设计，
  不是缺陷，但它意味着覆盖面靠持续维护这张表和模型的 `alias`。
- **一次一个问题**：不解析复合问句（"A 和 B 的差"），不做跨指标运算。
- **时间只有月/年/季度/相对词**：没有自然语言区间（"最近 30 天"），也没有节假日口径。
- **粒度不切换**：问"按季度"只会匹配到 `dim/quarter` 维度；不会把月度结果再上卷。
- **对比只做 yoy/mom**，按固定 365 天/期间长度平移，不处理"同口径日期对齐"（大促错位仍需人工）。
