# 两个端到端 Agent 实例

一个"Agent 实例"在这里是三样东西，缺一不可：

| 组成 | 文件 | 作用 |
| --- | --- | --- |
| **声明** | `agents/<id>.agent.json` | 问题、路由信号、用到的工具、**门禁与预算**、Skill 作用域、产物清单 |
| **运行器** | `examples/<id>.mjs` | 读声明 → 调真实模块 → 每一步打印数字 → 自检（不满足就退出非 0） |
| **产物** | `.pag/examples/<id>/artifacts/` | 报表、规则、审批记录、交接单、Skill —— 下一次运行或一个真人都能读 |

声明不是装饰：门禁与预算从 JSON 读，改一处 JSON 运行器就跟着变（`minZ`、`minPrecision`、`maxChangePct`…）。

```bash
npm run example:risk      # 风控策略：17 项自检
npm run example:growth    # 归因 + 市场决策：23 项自检
```

## 实例 1：风控策略（`risk-strategy`）

**问题**：「最近欺诈趋势如何？哪些特征真的有效？给我一条可以上线的规则，并告诉我它在离线上能抓多少。」

```
[1] 路由     agent=risk type=detective confidence=0.86（依据：欺诈、风控、规则、特征）
[2] 趋势     大区 3 在 2025-07 出现拐点：2.52% → 6.75%（z=6.04，样本 2854/934）
[3] 特征     可用 8/9；剔除未来函数 f_chargeback_30d（AUC 0.9355，as_of > event_date 15188 处）
             主特征 model_score_v1：AUC 0.9435 / KS 0.7668 / IV 3.9589 / PSI 0.038 / 单调递增
[4] 规则     2 条候选；首选 `f_blacklist_hit = 1`
[5] 回测     holdout P=0.8571 R=0.338 覆盖 1.49% lift 22.64（TP 24 / FP 4）
             与存量规则相比：新增抓到 6 个欺诈、重叠 67.9%、增量召回 8.45%
[6] 审批     审批前 published=0 → risk-lead@demo 批准 → published=1
[7] 经验     3 条 tip（特征有效性 / 规则回测 / 未来函数教训），全部带数值证据
```

自检覆盖（17 项，节选）：

- 路由确实到了风控，并给出依据，而不是一个标签；
- 拐点在注入月 ±1 个月内，且 `z ≥ minZ`（统计量而非"看起来涨了"）；
- **未来函数被 `as_of_date > event_date` 硬门拒绝**，哪怕它是全文件 AUC 最高的特征；
- 规则 ≤3 条件、holdout 上达到声明里的 precision/recall 门、混淆矩阵自洽、对存量规则有增量；
- **Agent 自己绝不发布**：批准前 `published=0`，批准后才出现，且带审批人与时间；
- 教训进入 Skill 库并可被检索。

**什么会推翻它**：把 `minPrecision` 提到 0.9（规则会被门禁拒掉，Agent 回退到"不推荐"）、把标签窗口改成上游还没回填的月份（holdout 只剩噪声）、或者删掉 `f_blacklist_hit`（规则只能靠组合特征，精确率掉到 0.5 以下）。

## 实例 2：归因 + 市场决策（`attribution-campaign`）

**问题**：「11 月花费为什么涨了？下一周期预算该往哪里调、调多少、怎么验证？」

```
[1] 路由     diagnostic（找原因）+ prescriptive（要动作）
[2] 归因     spend 2.27M → 4.91M，变动 2.64M（additive，残差 0）
             按大区：华南 +925.6k（35.0%）、华东 +… ；按渠道：搜索 +1.39M（52.7%）
             下钻：spend → channel = 搜索 → industry = 美妆个护
[3] 比率     ROI 2.0347 → 1.4727：分子（收入）项 +0.5338，分母（花费）项 -1.0958
[4] 投放     预算不变 3.41M；预计收入 5.80M → 6.70M（+902.5k，15.56%，曲线噪声 62.7k）
             加投：华东/3C数码/信息流 +64.9k（边际 0.947）…；减投：华南/3C数码/搜索 -151.2k（边际 0.275）
[5] 交接     handoff.md：发生了什么 / 怎么调 / 怎么验证 / 边界
[6] 经验     7 条 tip（批量取数、优先下钻维度、比率两因子、边际 ROI、曲线拟合、可信幅度…）
```

自检覆盖（23 项，节选）：

- 归因的切片**加总等于变化量**（误差 <1e-6），残差显式（本例 0）；
- 下钻至少两层；查询数 < 朴素切片数的一半（9 vs 42）；在预算内；
- 叙述**不含因果词**，且声明"是描述性分解"；
- 比率分解两项之和 = 变动，残差为 0；
- 投放：**预算守恒**、每个 cell 变动 ≤ ±50%、预计增益 > 曲线噪声（否则不该建议）、每个建议都挂曲线参数与 r²；
- holdout 有设计、有效应量、有样本量算术与可行性判断；
- 交接单四段齐全，且不含"保证 / 一定能"。

**什么会推翻它**：把窗口换成两个季节性相同的月份（spend 变动接近噪声，归因只剩零散切片）；把 `maxChangePct` 改成 0（无法移动 → 投放 Agent 拒绝）；或者数据没有饱和（`kind=linear`，边际≈平均，任何再分配都不产生增益 → 拒绝）。

## 怎么用它去接一个新域

1. 复制一个 manifest，改名、改问题、改门禁（这是**业务参数**，不是代码）；
2. 在 `fixtures/<新域>/scope.json` 里圈出属于这个域的表（别的域不要进这个模型）；
3. 语义模型跑一次 `npm run semantic -- build --graph <新域>`；
4. 运行器里替换成对应的子 Agent（风控用 `riskAgent`，增长用 `attribute` + `campaign`）；
5. 自检保留：**每个数字都要能被手写 SQL 或另一个模块复核**，否则它就不是实例，只是幻灯片。

## 诚实的边界

- 两个实例跑在同一份演示数仓上；真实环境里 ① 标签回填有延迟，② 特征仓有数十到数百个特征，③ ROI 曲线会被竞品与素材打断——门禁与 holdout 正是为这些而设，但它们不能替代真实实验。
- 风控实例的审批是**单签**（接口支持多条日志，流程未强制双签），实例里明确写出审批人。
- 增长实例的"预计增益"是曲线外推，实例把 `holdout` 与"±50%"写进交接单，是为了让它先被验证再被相信。
